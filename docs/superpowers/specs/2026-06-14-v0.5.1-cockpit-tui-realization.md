# Design: v0.5.1 "Cockpit TUI Realization"

**Date**: 2026-06-14
**Status**: implemented (slice 1 UX layer)
**Type**: corrective UX spec, refines [v0.5 Ouvrier Agent Cockpit](2026-06-13-v0.5-ouvrier-agent-cockpit-design.md)

## Why This Exists

The v0.5 spec defined the right product (a Pi/Codex/Claude-Code-class terminal
agent for building Ouvrier workers) and the right architecture (kernel + I/O
modes). What shipped after it, however, was UX-wise "a thousand miles" from Pi:

- the runtime `Prompt` was **fully blocking** — it returned a whole turn at once,
  so the operator saw nothing until the turn finished;
- the TUI was a **single static bordered panel** re-rendered every frame: the
  transcript was tail-truncated to 12 entries of 180 chars on one line each,
  tool calls were one-liners ("tool X started"), the composer was a single-line
  `textinput`, there was no status bar, no scrollback, no slash menu, no spinner,
  and `Esc` quit the program instead of interrupting.

The v0.5 spec was strong on architecture but light on the *concrete rendering and
interaction model* that makes Pi feel like Pi. This document pins that down and
records what was implemented.

## Streaming Contract (the enabler)

A good cockpit UX is impossible over a blocking turn API. The kernel now exposes
an incremental stream that every interactive frontend consumes:

```go
func (r *AgentRuntime) RunTurn(ctx, sessionID, text, kind string) (<-chan StreamEvent, error)
```

`RunTurn` runs the exact same plan/tool path as `Prompt` (so print/json/rpc stay
consistent) but emits events as work happens, and honours `ctx` cancellation
between tool calls — that is how `Esc` aborts a turn. Event kinds:

| Kind                | Meaning                                             |
|---------------------|-----------------------------------------------------|
| `user`              | operator prompt recorded                             |
| `status`            | non-persisted plan/preface line                     |
| `assistant_delta`   | incremental assistant text (typing effect)          |
| `assistant`         | final persisted assistant entry                     |
| `tool_start`        | a tool call began (name + input)                    |
| `tool_end`          | a tool call finished (output/summary, error flag)   |
| `error`             | turn-fatal error                                    |
| `done`              | terminal event for the turn (+ workspace snapshot)  |

`Prompt`/`Steer`/`FollowUp` are unchanged for callers; internally they share the
same `runPrompt(..., emit)` core with a nil emitter. Deterministic drivers (the
manual planner) get a synthetic typing effect via `emitAssistantDeltas`; real
streaming drivers can emit `assistant_delta` directly.

## TUI Rendering Model

The cockpit is a Bubble Tea program built from real components instead of one
re-rendered string:

- **Transcript** — `bubbles/viewport` scrollback. Content is a list of *blocks*,
  not raw events. `tool_start` + `tool_end` merge into one **tool card**.
- **Composer** — `bubbles/textarea`, multiline. `Enter` submits; `Alt+Enter` /
  `Ctrl+J` insert a newline.
- **Slash menu** — when the input is a bare `/token`, a filtered command menu
  renders above the composer; `↑/↓` select, `Tab` completes, `Enter` runs.
- **Status bar** — `state · model · worker · git · session · queued`, with a live
  `bubbles/spinner` and elapsed time while a turn runs.
- **Hints** — context-sensitive key legend (idle vs running).

### Block vocabulary

```text
❯ <user prompt>                      (bold, green caret)
● <assistant text>                   (cyan dot; trailing ▌ while streaming)
│ ⚙ <tool_name>  ✓ / ✗ / ⠋running    (tool card header)
│   key: value                       (selected inputs, max 4)
│   → <summary>                      (result; red on failure)
· <notice>                           (muted status line)
✗ <error>                            (red)
```

A failed tool renders its error inside the card; the standalone `error` block is
suppressed to avoid duplication. When a turn uses tools, the final concatenated
assistant message is suppressed (the plan block + cards already convey it).

### Keybindings

| Key            | Idle                         | Running                  |
|----------------|------------------------------|--------------------------|
| `Enter`        | submit prompt / run command  | queue follow-up          |
| `Alt+Enter`    | newline                      | newline                  |
| `Esc`          | close slash menu             | interrupt turn (`ctx`)   |
| `Ctrl+P`       | cycle model label            | cycle model label        |
| `PgUp/PgDn`    | scroll transcript            | scroll transcript        |
| `/`            | open command menu            | —                        |
| `?`            | help overlay (empty input)   | —                        |
| `Ctrl+C`       | quit (session saved)         | cancel + quit            |
| `1`-`9`        | select detected worker       | —                        |

Follow-ups submitted while a turn runs are queued and dispatched when the stream
closes (Pi's "submit while the agent works"). True mid-turn steering remains
future work because the deterministic planner runs turns atomically.

## Out Of Scope Here

- A real streaming Codex/model tool-calling loop (the planner is still
  keyword-driven; the streaming UX is now ready to host a real driver).
- Interactive plan-approval and review-inbox drawers (next slice).
- Streaming RPC (`RunTurn` over JSONL) — current RPC stays request/response.

## Product Bar (met)

The operator can now sit in `ouvrier operate`, type a goal or `/command`, and
watch the agent work **live** — assistant text types in, tool cards appear and
resolve with ✓/✗, the status bar shows model/worker/elapsed, and `Esc` interrupts
— inside one scrolling terminal interface. That is the Pi-shaped experience the
v0.5 spec asked for.
